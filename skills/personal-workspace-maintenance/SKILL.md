# Workmoire Maintenance

Use this skill for changes to the Workmoire source, tests, deployment, GitHub synchronization, runtime data boundaries, or the project's own maintenance workflow. It applies when a request mentions this project, its Tencent Cloud service, its public repository, or an optimization to the workflow.

## Core invariants

- The Git repository is public-safe source. Never commit personal notes, papers, work logs, uploaded files, SQLite databases, backups, production .env files, server addresses, usernames, SSH material, access tokens, cookies, logs, or generated runtime state.
- Runtime data stays outside the checkout in the configured WORKSPACE_DATA_DIR. Treat the database and file directory as user data and back them up before schema changes or destructive operations.
- Unsaved editor drafts are browser-local convenience data. They may be restored only when their saved-item revision still matches. They stay local by default; only an explicit assistant action may send the current selected text to the configured local Codex, and that text must never enter repository files, server logs, or exports automatically.
- Keep normal content and file deletion reversible through the authenticated trash area. Permanent deletion must be a separate, explicit operation and must remove the corresponding file bytes.
- Keep batch organization actions authenticated, bounded to a small explicit selection, and transactional. Batch status changes must leave item history; batch trash must remain reversible and detach affected hierarchy links without exposing partial results.
- Keep the batch-selection affordance visible before any item is selected; reveal destructive or state-changing actions only after selection so the fast path stays discoverable without making accidental changes easy.
- Keep navigation collapse and label filtering independent of document edits. Label suggestions must remain explicit selections and follow normal draft/save boundaries. Global label renames/merges require a bounded impact preview, transaction-time version validation and original document revisions; exclude trashed content and preserve unrelated labels and rich content.
- Keep catalogue label controls beside pin and use explicit metadata saves for existing documents. These saves must be revision-checked, record history, and preserve unsaved body/native edits; only rebase a matching local draft over the known label-only update. New-document labels stay local until document save. Built-in labels must exist at zero usage and be protected server-side; paper classification must remain consistent for legacy reads, filters and saves without rewriting records on startup. Use stable, readable bookmark colors with text labels.
- Keep label creation and full maintenance discoverable in that same entry. Creation and Enter must work independently of pending suggestions; adding/removing an association should give immediate saved-state feedback. Distinguish removal from the current document from shared-label deletion. Shared rename/delete require a bounded preview, operation-specific version token and retained revisions; return before/after metadata so matching drafts can advance without replacing text.
- Keep the application single-user unless the user explicitly changes that product decision. Passwords are set through the first-run page and are never placed in source, documentation, chat, or deployment commands.
- Protect first-run setup with `WORKSPACE_SETUP_TOKEN` whenever the service is reachable beyond localhost. Keep the token in the private environment file and never commit or print it in deployment logs.
- Enforce the first-run boundary in code: a non-loopback listener without `WORKSPACE_SETUP_TOKEN` must return an error before creating the account, and `/api/session` must expose that token requirement so the setup form cannot silently omit it. A reverse proxy can make a loopback bind public, so configure the token there too.
- Keep direct HTTP connection handling bounded: the custom server must use daemon worker threads, an explicit request queue, and a finite socket read timeout. Prefer HTTPS termination and stronger rate/connection controls at a production reverse proxy.
- Protect edits against silent multi-tab overwrites: clients send the last `updated_at` they loaded, and the server returns the current item with `409` on a stale base. Preserve the user's unsaved changes as a local draft before offering to load the newer server version.
- Keep public sharing in a separate unprivileged process, environment and port. Publish only explicit saved snapshots and their referenced attachment copies; never give the reader access to the private workspace database, assistant credentials or publisher key. Different ports do not isolate cookie hosts; recommend a separate HTTPS hostname for transport and browser separation.
- Require high-entropy opaque link tokens for every share. Password protection defaults on; only an explicit authenticated boolean choice may disable it for that snapshot and its media. Preserve protection for existing shares on migration. Re-enabling protection keeps the link but rotates the password and invalidates earlier sessions. New/reset passwords use 16 alphanumeric characters including uppercase, lowercase and digits; version password derivation so existing credentials stay unchanged on upgrades/expiry changes. Copy protected credentials as exactly two lines: link and password; copy only the URL when protection is off. Recheck expiry, revocation, protection mode and applicable credential versions on every content/media request; preserve brute-force limits across restarts and keep tokens/passwords out of logs. Trash must revoke shares, and restore must not reactivate them. Back up the publication database, publisher key and media consistently under the publisher lock, excluding reader sessions.
- Keep the service independent of other applications on the server. Discover a free port before changing it, preserve existing services, and verify the service health after every deployment.
- Keep the project reproducible from a clean checkout. Prefer Python standard-library code and documented Docker/systemd paths unless a dependency has a clear user-facing benefit.
- Keep the local Codex assistant disabled unless `WORKSPACE_CODEX_BIN` is explicitly configured on the private server. It may receive only the selected document through standard input, must run in ephemeral read-only mode, and must never expose arbitrary command execution or persist prompts and responses. Use a bounded reasoning setting by default so a web request remains responsive; make model and reasoning overrides explicit private configuration.
- Treat the assistant CLI flags as the security boundary: pass `--ephemeral` and `--sandbox read-only` explicitly on every invocation, and do not rely on profile keys that the installed CLI may ignore. When the CLI is upgraded, verify its version, help output, and a synthetic invocation before enabling it for personal content.
- Verify assistant deployment with the running service's exact environment, including `CODEX_HOME`, provider credentials, and proxies; an interactive-shell test can hide a broken systemd configuration. Use synthetic input via `scripts/check_assistant.py`, never print environment values or authentication data, and terminate the entire CLI process group on timeout.
- Treat assistant output as a user-reviewed suggestion: display it without mutation first, require an explicit insert action, keep uninserted previews out of the editor and storage, and persist explicitly inserted content through the normal manual or background-autosave path.
- Treat imports as user-data migrations: accept only the versioned Workmoire export format, run them in one transaction, rebuild relationships through an ID map, and never import credentials or file binaries.
- Back up the configured data directory before schema or deployment changes. Use `backup.sh` (or an equivalent SQLite backup API) for the database and archive uploaded files; keep backups outside the checkout and apply an explicit retention policy.
- After deploying backup scripts, execute a backup as the configured service user and verify the completed systemd backup job. An active timer does not prove the script is executable.
- Treat a backup as valid only after the SQLite snapshot passes `PRAGMA integrity_check` and the uploaded-file archive can be listed successfully; perform those checks before retention pruning.
- Keep automated public-boundary checks generic: never embed a real deployment address, personal domain, or other private identifier as a denylist fixture. Use synthetic patterns in CI and review actual addresses, emails, and paths before publishing.
- Keep search ranking deterministic and privacy-preserving: rank metadata matches ahead of body-only matches without exposing deleted content or adding an external indexing service.
- Open search and activity results through an authenticated item lookup rather than assuming the current client list contains the result; navigation must remain correct when list views are bounded or filtered.

- Keep current-version metadata tied to the deployed package/revision. Place the sidebar version beneath the full wordmark so longer versions cannot truncate the project name; verify narrow layouts, font fallback and scaling. GitHub update checks must be authenticated, bounded and cached, send no private data, and distinguish no release from network failure. Preserve editor drafts when opening About.

## Document and paper workflow

- Keep the main interface centered on documents, papers, and a simple relationship view. Expose exactly two creation choices: blank document and paper materials. Blogs, plans, ideas and checklists belong to ordinary notes/tags. Preserve legacy records and drafts; do not delete user content when removing specialized creation flows.
- Keep interface copy functional: labels name actions, empty states explain the next step, and placeholders describe accepted input. Do not add motivational slogans, background taglines, or decorative English headings that duplicate the page title.
- Prefer a restrained document-tool visual style: neutral surfaces, clear text contrast, locally hosted variable sans-serif type with platform fallbacks, moderate shared corner radii, and one interaction accent. Avoid the rejected green/cream palette, pastel category decoration, oversized illustration panels, and unnecessary gradients or shadows. Apply shared visual tokens consistently to controls, dialogs, editor surfaces and the PDF reader; verify actual Chinese glyph fonts rather than relying only on a declared CSS stack.
- Bundle editor, Markdown, math, syntax-highlighting assets, interface icons, fonts, and license notices locally with locked dependencies. Reused illustrations must retain pinned upstream sources, licenses, and intrinsic aspect ratios; verify responsive editing and PDF controls on actual synthetic browser pages. Disable raw Markdown HTML and trusted LaTeX commands.
- Keep media authenticated. Inline viewing requires byte-verified PDF or safe raster-image signatures, never the upload's MIME claim. Keep HTML/SVG as downloads, preserve the default anti-framing policy, and permit same-origin framing only for verified inline media and the fixed trusted PDF viewer page. Test PDF range responses and selectable-text rendering without relying on native PDF plugins.
- Paper intake requires a manually uploaded PDF. Optional source URLs are attribution only: never resolve, fetch or download them in preparation or analysis. Keep automatic PDF download controls and legacy online lookup/import endpoints disabled server-side as well as in the UI. Existing external PDF blocks retain only their source link and a manual-upload hint; preserve already-stored attachments and documents.
- Use only the supplied PDF and its locally extracted text for preview and analysis. Replacing the selected file invalidates earlier extraction/notes, and only the final file is linked on save. Bound PDF.js text extraction; keep textless PDFs readable without fabricated analysis. Discard temporary imports through recoverable trash.
- Paper profiles use one bounded structured response for facts, fields and the brief. Check factual excerpts against the supplied PDF, support explicit correspondence markers, and omit unsupported fields and empty sections from rendered notes. Keep evidence checks internal; field classification needs supporting source text, without a visible explanation; generate at most two distinct selectable field tags plus the built-in paper tag. Preserve reviewed analysis across title/author/source edits, invalidate it on file replacement, and write tags only through normal document save.
- When adding a document kind requires expanding a SQLite CHECK constraint, use an atomic table replacement after a backup and a private-copy rehearsal. Preserve all rows, foreign-key targets, indexes, triggers and autoincrement state; verify integrity/references and restore enforcement on failures. Never downgrade by deleting records of the new kind.
- Paper lookup/draft endpoints must not create documents, files, or revisions. Explicit insertion creates unsaved editor text; normal save is the persistence boundary. Keep local Codex invocations in disposable empty directories and read their final-message file before cleanup.
- Autosave defaults on for existing and meaningful new documents; do not create empty placeholders. Use stable creation request keys and an authenticated private ledger so lost responses cannot duplicate notes or overwrite later edits/deletions. Keep the ledger out of exports/shares and rehearse additive migrations on a private copy. Use the existing revision-checked save path, serialize writes, wait for IME/tag edits, synchronize text independently of pending uploads, and retain edits made during requests. Keep a top-right failure notice recommending a pause in editing until current changes are confirmed saved; typing/retrying/online events must not clear it. Distinguish network/service/auth/conflict/validation failures, cap transient retry frequency, and pause on permanent failures. Report local-draft failures honestly. Keep share snapshots explicit. Coalesce only consecutive automatic history checkpoints with matching revisions; manual/intervening updates and restarts must create fresh checkpoints.
- Preserve edits made during in-flight saves. Keep drafts revision-scoped; stale drafts may be copied for manual merging, never silently restored over a newer revision.
- Treat the native ProseMirror document and its Markdown mirror as one revision. Validate the versioned JSON, preserve it through history and JSON/ZIP imports, and remap document/file references together. Check the Markdown hash before loading native state so older clients or rolled-back servers cannot display stale rich content. Keep migrations additive and verify them on a private database copy.
- Verify IME fixes with real browser composition updates, including shrinking/cancelling candidates; synthetic keyboard/composition events alone do not reproduce browser-owned composition ranges. Shortcut handlers must not dispatch empty transactions during active composition. Keep native input events and DOM parsing active, and preserve ordinary Backspace/list behavior after confirmation.
- Store explicit Bug reports privately with authenticated, immutable records and scoped screenshots. Do not auto-capture documents, cookies or logs; uploads happen only on submit. Bound and byte-check images, make retries idempotent, roll back only files owned by the failed operation, and include records/images in private backups without exposing them through document exports or sharing.
- Keep slash commands discoverable in Chinese and English. Maintain explicit aliases, including user-defined shorthand, full pinyin and initials; rank exact matches first, require all query terms to match, and preserve text on cancellation or no match. Test keyboard insertion and Chinese composition before shipping search changes.
- Keep the document outline beside the body in editing and reading modes, separate from metadata panels. Preserve heading identity through edits/undo, track scrolling and layout changes without serializing Markdown, and keep navigation outside document/selection history. Close narrow-screen navigation without losing drafts or recreating PDF frames; remove listeners and observers on document changes.
- Keep typing incremental: no whole-document Markdown parsing, serialization, or iframe replacement per keystroke. Exercise real input, Chinese composition, formatted paste, table/image resizing, block moves with undo, PDF state retention, and a long synthetic document. Report draft-storage failures instead of silently claiming a local copy exists.
- Keep whole-document font choices in validated native metadata and normal save/history/share boundaries. Font-only history must not recreate PDF/node views or serialize Markdown unnecessarily. Keep selection colors scoped to the selection, expose common formatting once in the toolbar, and give icon controls hover/focus names and shortcuts. Bundle any added fonts locally with licenses and keep code/math faces independent.
- Keep the main toolbar on one line with reachable overflow at narrow widths. Position menus outside scroll clipping and preserve tooltip/selection behavior. Keep title spacing compact; the editor footer contains only matching document-link and Bug-report actions and is hidden in focus mode. Preserve the single reporting entry across document teardown, mobile list navigation and resizing.
- Keep focus mode centered on the document: use a compact header and on-demand formatting, omit persistent metadata/auxiliary actions, and keep save/mode/exit controls reachable. Move existing title/mode/outline controls instead of rebuilding document or PDF nodes; preserve unsaved values, selection, reading anchors and PDF state, and restore the regular layout on exit.
- Keep Tab local to editable text: native paragraph/heading indentation, list nesting, code-line indentation and table-cell navigation must preserve selection, undo and IME composition. Provide a keyboard exit to the toolbar and retain normal navigation for other controls/read-only views. Validate bounded native indent attributes and preserve them through history, archives and sharing without turning prose into Markdown code.
- Keep inline code boundaries open to ordinary or differently formatted text, including paragraph starts and native IME input. Boundary exits change typing marks only: never persist zero-width placeholders or automatic spacer text. Preserve explicit code toggling, interior edits, selection, undo and saved content; stored-mark-only changes update toolbar state without dirtying documents.
- Keep tables bounded to the body by default; free-width scrolling must be explicit per table. Column distribution and resizing must respect colspan/rowspan, preserve content, and participate in native save/history/export/share boundaries. Resize fixed tables by redistributing adjacent columns; treat viewport adaptation and scrollbar positions as view state. Verify cancellation, narrow layouts and accessible horizontal scrolling.
- Keep code folding lossless: explicit editing folds belong to native document history, while reading/search overrides and code themes must not dirty the document. Preserve full source through copy/export, reveal search hits before scrolling, and keep the editing caret out of hidden content. Verify font loading, syntax contrast and local scrolling at narrow widths when changing code presentation.
- Keep LaTeX blocks as validated native nodes with bounded source text, local KaTeX rendering, explicit Write/Preview state and normal save/history/export/share boundaries. `/latex` must be discoverable through the local slash vocabulary; public readers stay preview-only. Do not allow raw HTML or untrusted TeX trust features.
- Keep document outlines readable in focus mode and shared readers: widen the focus rail within the available body, provide a collapse/reopen control that is view state, and rebuild shared outlines from the read-only native document without exposing edit controls. Test long headings, duplicate levels, mobile toggles and cleanup on document changes.
- Keep the reading desk as a view of existing notes and uploaded PDFs. Preserve editor selection/drafts and reader instances through resizing, mobile tabs and focus changes. Store bounded local reading state by file identity and reading context, without publishing it. Insert text quotations only on an explicit action and save normally; preserve page citations through validation, history, Markdown, archive remapping and scoped sharing. Verify message origin and the exact reader window before accepting bounded quote/capture/shortcut data, and keep public readers read-only. Validate bounded normalized geometry and fingerprints through save/export/share, highlight only matching PDFs, and upload region images only after confirmation. Preserve input and mapped selections during capture uploads; cancel before confirmation creates no files.
- Keep paper reasoning/model/timeout settings separate from quick document tasks. Paper analysis currently prioritizes a concise, source-grounded brief with medium reasoning; keep its versioned prompt separate from business code. Use the selected uploaded PDF text and bound the excerpt; show extraction coverage in the import UI, without adding process commentary or reviewer-style caveats to the document. Explain core insights and technical mechanisms. Include a bilingual abstract only when the original matches the supplied text, before the brief. Do not fetch HTML or a substitute PDF. All reasoning settings must preserve preview, insert, and explicit-save boundaries.
- Keep progress honest: upload bytes and extracted pages are measured, AI completion percentages are explicitly estimated from recent durations and never reach 100 before results arrive. Separate transfer from server acknowledgement, disclose overruns, scope transient jobs to the authenticated owner, and persist only content-free timing samples. Prefer local extraction of the supplied PDF in parallel with streaming upload; preserve exact file priority and recovery paths. Exercise valid long PDFs that exceed the text cap, cancel PDF.js streams with an Error reason without waiting for an acknowledgement from an already-closed sink, destroy the loading task, and retain successful upload status when extraction fails.
- Ship local runtime license notices and deterministic compressed static assets together. GET/HEAD must negotiate gzip consistently and reject stale compressed copies in favor of the current source.
- Exercise the actual browser on synthetic data after editor/navigation changes: formulas, code/tables, task clicks, paste/drop, PDF viewing, paper generation/insertion/save boundaries, conflict/draft handling, relationship navigation, and narrow screens.

## Working workflow

1. Read the repository instructions and inspect the current branch, service unit, data path, port, and resource headroom before editing.
2. Work in the Git checkout. Keep production data in a separate ignored directory. Make schema changes backward-compatible and test them against a copy of the database before touching production. Verify that deleted content is hidden from active queries and can be restored.
3. Treat the repository skill at skills/personal-workspace-maintenance/SKILL.md as the source of truth for this workflow. If a workflow invariant or repeatable operational lesson changes, update this skill and its relevant reference in the same change.
4. Run the project's checks before deployment: make compile (including `bash -n backup.sh`), make test, node --check workspace/static/app.js, the isolated browser suite, and an HTTP smoke test covering health, first-run session state, authentication, content CRUD, file upload, and assistant-disabled behavior when those paths changed.
5. Run a public-repository scan before staging and again before pushing. Check for IP addresses, personal email addresses, private paths, credentials, private keys, tokens, cookies, database files, uploads, logs, and non-placeholder production settings. Review the staged file list manually.
6. Deploy only source files and static assets to the configured application directory. Do not copy .env, data/, backups, or a whole working directory. Restart the systemd service only after the new files are in place, then verify systemctl is-active, /healthz, /api/session, the listening port, and recent journal output. If backups are enabled, verify the timer, one completed snapshot, SQLite integrity, archive readability, and retention behavior without exposing backup contents.
7. The owner has given standing authorization to synchronize substantial completed changes to `ZAIQuQ/Workmoire`, branch `main`, after tests and deployment verification. Update the semantic version, changelog and both README languages; commit, deploy the exact revision, push without force, create its version tag/Release and inspect GitHub CI. Do not ask for push permission again. Keep the deployed and released revisions aligned and follow `docs/releases.md`. If a remote is missing, verify the established repository and source history before reconnecting it. If authentication is unavailable, complete reviewable source/deployment work and report the specific login blocker; never claim an unpublished local commit was synchronized.
8. Report what changed, what was tested, the public repository state, the deployment state, and any remaining setup such as a cloud security-group rule or HTTPS.
